# FPVSIM

Симулятор FPV-дрона від першої особи на Three.js. Злітаєш із трави, шукаєш ціль по квадратах,
виходиш на неї. Без стрілок-маркерів і без мінімапи в польоті: єдина навігація — компас,
брудне аналогове відео та те, що ти запам'ятав із брифінгу.

Дизайн-документ і правила проєкту — у [CLAUDE.md](CLAUDE.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173 (або наступний вільний порт)
npm test           # 307 тестів
npm run build           # tsc --noEmit + vite build → docs/
npm run preview         # перевірити зібрану статику так, як її роздасть Pages
```

Службові сторінки (тільки в dev, у збірку не входять): `/models/` — вибір моделей,
`/probe.html` — огляд моделей у світі рівня без польоту.

Параметри URL: `?level=8` — стрибок одразу на потрібний рівень (1–15),
`?sens=0.6` — множник чутливості стіків, щоб підібрати відчуття без перезбирання.

## Прогрес кампанії

Прогрес зберігається в `localStorage` (`fpvsim.progress`): пройдені рівні, поточний рівень
і номер вильоту всередині нього. Рівні відкриваються по черзі — кампанія побудована
як прогресія навичок. Скинути можна кнопкою RESET PROGRESS на екрані вибору рівня.

Пройдений рівень можна перепроходити скільки завгодно: він лишається відкритим, а курсор
«CONTINUE» від цього назад не з'їжджає — він завжди вказує на перший **непройдений** рівень.
Вийти в меню кампанії можна з брифінгу (CAMPAIGN), з дебрифу (CAMPAIGN) і прямо з польоту (`Esc`).

Сховище за інтерфейсом (`src/game/progress.ts`), тому приватний режим, заблоковані куки
чи переповнена квота гру не ламають — у найгіршому разі прогрес не переживе перезавантаження.

**UI повністю англійською**; коментарі в коді та назви тестів лишились українською —
це документація для розробника, а не текст для гравця.

## Публікація

Гра лежить на GitHub Pages **без Actions і без CI**: `npm run build` кладе готову
статику в `docs/`, і вона комітиться прямо в репозиторій.

`base: './'` у `vite.config.ts` — навмисно **відносний**. Абсолютний base прив'язує
збірку до однієї конкретної адреси, і варто Pages роздавати сайт з іншої папки —
усі асети дають 404. З відносним шляхи працюють звідусіль:

- Pages роздає з кореня → гра за `.../fpv-simulator/docs/`
- Pages роздає з `/docs` → гра за `.../fpv-simulator/`
- власний домен або локальний статичний сервер → теж працює

Правило: **змінив код — перезбери й закоміть `docs/` разом зі змінами**,
інакше на Pages лишиться стара версія.

## Керування

| Дія | Клавіатура | Геймпад (mode 2) |
|---|---|---|
| Газ | `W` / `S` (накопичувальний) | лівий стік ↕ |
| Рискання | `A` / `D` | лівий стік ↔ |
| Тангаж | `↑` / `↓` | правий стік ↕ |
| Крен | `←` / `→` | правий стік ↔ |
| Заглушити мотори | `Space` | A |
| Рестарт рівня | `R` | Start |
| Вийти в меню | `Esc` | Select |

Окремого «арму» немає: мотори піднімаються від першого руху газу — злітати треба
одним рухом, а не пам'ятати про службову кнопку. `Space` лишається аварійним
глушінням у польоті.

Карта наповнена лісосмугами, чагарником, фермами, стогами й ЛЕП. **Усе це тверде** —
влетів у дерево чи будівлю, і борт втрачено; у дебрифі буде сказано, у що саме.
Об'єкти генеруються детерміновано з того самого seed, що й рельєф, і ніколи не
з'являються на точках зльоту чи на маршрутах цілей.

Пояснення керування показується при першому запуску й далі доступне
кнопкою CONTROLS на екрані кампанії.

Дрон **не зависає сам** — газ тримає пілот. Усі рівні йдуть в ACRO без автовирівнювання:
стік **тапають**, щоб задати нахил, і відпускають — нахил лишається, поки не рухаєш стік
знову. Утримання стіка в ACRO — це безперервне обертання, а не «летіти вперед».

У клавіатури немає аналогових осей, тому вона отримує два асисти (геймпад — жодного):
відпущений газ повертається до зависання з поправкою на нахил, а осі крену/тангажу/рискання
плавно виходять на край за ~0.28 с і швидко вертаються в центр. Легкий тап = мале відхилення.

## Структура

```
src/
  flight/    ядро польоту — чистий TS, БЕЗ three.js, тому тестується в node
  drones/    характеристики дронів і навантажень — самі дані
  level/     рельєф із seed, наповнення карти (props), сітка квадратів, рівні
  game/      цілі, маршрути, правила місії, збірка вильоту
  render/    світ, FPV-камера із затримкою відео, аналоговий тракт, моделі техніки й наповнення
  ui/        вибір рівня, брифінг-мапа, OSD, дебриф
  core/      ввід, звук
tests/       307 тестів; playable.test.ts проходить автопілотом усі 22 вильоти
```

Два правила, які тримають проєкт: **уся поведінка — в даних** (новий дрон або рівень
не потребує коду) і **`flight/` не знає про рендер** (тому фізику видно в тестах, а не на око).

## Що вже відчувається по-різному

Виміряно, а не заявлено — порядок закріплено в `tests/payload.test.ts`:

| Дрон | TWR (без БК) | Максимальний темп крену | Досягнуто за 50 мс |
|---|---|---|---|
| 7" тренувальний | 4.1 | 308 °/с | 148 °/с |
| 7" легкий | 3.5 | 213 °/с | 83 °/с |
| 8" середній | 2.8 | 151 °/с | 37 °/с |
| 10" важкий | 2.6 | 114 °/с | 17 °/с |

Останній стовпець — те, що пілот відчуває як «різкість»: тренувальний виходить на темп
у **8.7 раза** швидше за важкий. Самі криві навмисно фристайлові, а не гоночні
(було 686–233 °/с): гра про пошук і точний захід, а на гоночних кривих будь-який дотик
стіка збиває лінію на ціль.

Навантаження додає до цього три ефекти: ріже запас тяги, сповільнює обертання
(крен/тангаж — так, рискання — ні) і опускає центр мас, через що дрон гойдається
маятником після кожного різкого стіка.

## Діагностика

```bash
PROBE=1 npx vitest run tests/probe.test.ts   # відгук, TWR, максималка, маятник
```

У режимі `dev` глобальна змінна `window.fpv` дає доступ до `session`, `world`, `camera`.
